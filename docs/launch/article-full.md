## 开头

开会 1 小时，整理纪要 2 小时——这个场景你一定不陌生。

更麻烦的是：很多会议录音是**不能随便上传的**。工程监理例会有验收责任、客户拜访有商业信息、面试记录有个人隐私。市面上大多数“AI 会议纪要”工具都是云端 SaaS：录音上传、按分钟计费、数据过第三方。对敏感会议来说，这条路根本走不通。

所以我把整套流程做成了**本地优先**的版本：录音进，纪要出，数据不出门。

## 它解决什么问题

一个完整的会议纪要工作流通常要五步：

1. 录音转写（ASR）
2. 判断这是什么会（场景识别）
3. 生成结构化纪要（大模型）
4. 质量复核（防止编造事实）
5. 导出交付（Word / PDF）

云端方案把 1、3、4 全部外包给厂商，代价是隐私和费用。本地方案则全部在你自己机器上完成：

- 转写：FunASR `paraformer-zh`，中文会议识别效果好，CPU 就能跑；
- 场景识别：规则证据门控 + 本地大模型复核；
- 纪要生成：Ollama 跑开源模型（默认 `qwen2.5:7b-instruct`）；
- 导出：工程例会、通用纪要、个人备忘、面试记录、客户拜访五套原版式模板。

## 三个关键设计

### 1. 规则证据门控：模型不能“看着像就套模板”

工程例会和普通周会长得有点像：都聊进度、质量、安全、验收。

如果直接让模型判断，很容易出现“说了一嘴项目进度就被套上工程模板”的误判。所以实现是：先用本地规则分析转写里的**证据链**——是否有施工/监理/建设多类责任主体、是否有生产控制议程、是否有周期复盘与责任时限——证据不足就保守归入通用纪要。模型只做复核，**不能推翻强证据**。

### 2. 长录音容错：单段失败不整段作废

三小时的会议转写，任何一段网络或模型抖动都不该让整场作废。实现上自动分块、并行提取、失败段留占位标记，最后合成时缺失可见，绝不“假装完整”。

### 3. 质量复核：生成后还要过一遍

纪要生成后自动执行第二轮事实/模板/责任闭环检查：禁止补造姓名、单位、时间、评分、承诺；原文没提到的信息一律写“待确认”，不留示例数据。

## 快速体验

```bash
git clone https://github.com/wenxuanzhang1209-cyber/jkinco-listen-open.git
cd jkinco-listen-open
cp .env.example .env
docker compose up -d --build
```

打开 `http://localhost:8080`，默认账号 `admin / 123456`。

首次启动自动下载本地 ASR 模型（约 1–2GB）和默认大模型（`qwen2.5:7b-instruct`），之后**完全离线可用**。

## 工程化程度

- 891 个自动化测试：API、安全、并发、模板、导出、场景规则全覆盖；
- CI 四道流水线：红线扫描（禁止云端模型痕迹与密钥混入仓库）、后端测试、前端构建、Docker 镜像构建；
- 登录限流、验证码、会话签名、CSP 安全头、模板上传防 Zip 炸弹；
- MIT 开源，可商用。
